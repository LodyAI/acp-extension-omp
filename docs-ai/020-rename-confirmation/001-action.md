## 相对计划的偏差

- 「标题已送达、确认未发出时失败」用例最初断言得太早：去掉第二次守卫它也通过。主 agent 做变异检查时发现，改成等标题通知的 handler 返回、再多等一个宏任务才断言。计划只写了在 handler 内同步关闭连接，没有写这一步等待。
- 探针没有单独断言“会话文件路径不变”。这一点由适配器自己的身份核实间接证明：`get_state` 读回的 `sessionFile` 不等于原文件时 prompt 会失败，而两次实测都是 `end_turn`，之后的普通 prompt 也用同一个 `sessionId` 完成。

## 未验证的问题

- `npm run contract` 和发布矩阵没有在本改动上重跑。`COMPATIBILITY.md` 里通过的行仍是 `d6362de` 上的证据。
- 确认文字在 Lody 里怎样持久化和渲染、对推送通知和统计的影响没有核对。只核对了它算可见输出、不影响标题生成。

- server 层「确认文字写入失败」用例只证明关闭和回收。“不返回成功”由 connection 层的发送抛错用例证明。

# 004.002 — Lody 独立审核结果与修复

## 背景

[001-action.md](001-action.md) 写了「本条目的改动还没有被独立审核」。之后由 Lody 中的一个 Claude Code 会话（不是实现者）对 `f23977b..ed7f6f5` 做了两轮只读审核。结论是 LDY-002、003、004、006 已关闭，没有 P1 和 P2，新提出 4 条 P3。

## 变更

| ID | 问题 | 处理 |
| --- | --- | --- |
| LDY-009 | Linux 上，如果孤儿进程的回收者不及时回收僵尸（例如容器里 PID 1 是 node），僵尸仍然属于原进程组，`groupAlive` 会一直判为存活，适配器约 2 秒后误报失败、以 code 1 退出 | 不改代码，记为已知限制。这是推断，没有在容器里验证。要修就得逐个检查组内成员的状态（如读 `/proc`），超出本条目的范围。在用户本机上，launchd 或 systemd 会及时回收僵尸 |
| LDY-010 | `graceEnds`、`forceEnds` 和 `waitUntil` 用的是 `Date.now()`，系统时钟往回调时，关闭期间的等待会被拉长，等价于挂住 | 已修：改用单调时钟 `performance.now()`。这是在已核对规格范围内修正实现。RED：替身用例在关闭开始后把 `Date.now` 往回拨 60 秒，修复前 `close` 直到 6 秒超时都没完成；修复后约 2 秒完成 |
| LDY-011 | 计划目标 4（OMP 退出后最后的输出不丢）没有测试，「第二个宽限期内释放」的断言上限也过宽（6 秒） | 已修，见下 |
| LDY-012 | README 说所有子孙进程都会被回收；实际只回收仍在 OMP 进程组里的 | 已修：README 改为只回收仍在 OMP 进程组里的子孙进程，并写明用 `setsid` 等方式离开进程组的子孙进程不会被回收，Windows 上的所有子孙进程也不会被回收 |

LDY-011 的修复：

- 新增替身用例：OMP 退出 300 ms 后才往 stderr 写最后一行并结束管道，断言这一行被转发到 `process.stderr`。
- stdio 释放用例的上限从 6 秒收紧到 `STDIO_RELEASE_BOUND_MS`（2.5 秒）。

用变异验证这两个测试能抓住回归，每次都从备份恢复源码：

| 变异 | 结果 |
| --- | --- |
| 退出后立即销毁 stdio（期限设为 0） | 新的最后输出用例失败：期望含有 `omp: final diagnostic`，实际为空字符串 |
| 释放期限放宽到 `graceEnds + 5_000` | stdio 释放用例失败：6 秒超时 |

已执行（Darwin 27.0.0 arm64，Node `v26.10.0`）：

| 命令 | 结果 |
| --- | --- |
| `npm run check` | PASS：类型检查通过；3 个测试文件、36 项；没有残留夹具进程 |

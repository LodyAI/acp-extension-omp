# 012.010 — R1：18.12.6 macOS arm64 合同记录（f03e5d2 之后）

## 背景

提交 `f03e5d2` 让 `prepareSession()` 先请求 `get_available_models`，并按 `ompModelsSchema` 与 `modelConfiguration()` 校验。之后 `npm run contract` 在本机 OMP 18.12.6 上失败：真实 OMP 段符合预期，失败点在 `scripts/contract.mjs` 的 `syntheticCases()` 第一个夹具客户端。`session/new` 返回 -32603 `OMP did not return an available model catalog`，原因是合成夹具 `fixture.cjs` 对 `get_state` 以外的命令都只回 `data: {}`。适配器行为和断言本身没有错。

## 变更

只改了 `scripts/contract.mjs` 内生成的合成夹具，没有改 `src/`、`test/`、断言或 Required cases：

- 夹具 `get_state` 返回 `{ sessionFile: identity, model }`，其中 `model = { provider: "fixture", id: "a", name: "Fixture A" }`。
- 夹具 `get_available_models` 返回 `{ models: [model] }`，即只含当前模型的最小合法目录，满足 `ompModelsSchema`，也满足 `modelConfiguration()` 的「当前模型必须在目录中」约束。
- contract 不调用 `session/set_config_option`，所以夹具没有补 `set_model`。

夹具的 usage 帧仍用 `fixture/a`、`fixture/b` 计费，与目录无关；用例 7 的断言没有变化。
